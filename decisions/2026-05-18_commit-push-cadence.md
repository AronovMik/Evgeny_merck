# 2026-05-18 — Периодичность коммитов и пушей

## Решение
Содержательные изменения в репозитории пушим в GitHub как можно скорее (после каждого логически завершённого шага), не дожидаясь конца сессии. Чисто разговорные обмены, не порождающие артефактов, не коммитим и не журналируем.

## Контекст
Среда Claude Code эфемерная: контейнер сессии живёт ограниченное время, и при его очистке всё, что не было запушено в `origin`, теряется. Дополнительно — нет гарантий, что аккаунт Claude всегда будет доступен в текущем виде. GitHub в этой связке — единственная долгосрочно надёжная точка хранения.

Запрос Евгения (дословно): «если я переключился в другую сессию, то более-менее базовые обсуждения, которые соответствуют теме, были запушены как можно быстрее. Если вдруг что-то случится с текущим аккаунтом клод, я должен быть уверен, что все есть в гитхаб». При этом чисто служебные разговоры (например, объяснения «что такое коммит») пушить не нужно — они засоряют историю.

## Правило (закреплено в `CLAUDE.md`, раздел «Когда коммитить и пушить»)

**Пушить ASAP:**
- Новые / изменённые файлы в `tasks/`, `context/`, `decisions/`, `ideas/`, `templates/`, `archive/claude-chats/`.
- Обновления `CLAUDE.md`, `INSTRUCTIONS.md`, `STATE.md`, `TODO.md`.
- Журнал по реальной работе.
- Триггер: завершён логически законченный шаг → `commit` + `push` сразу, потом продолжаем.

**Не пушить и не журналировать:**
- Объяснения «что такое X», вопросы про устройство Claude Code / git / среды.
- Общие обсуждения, не приводящие к изменениям в репозитории.
- Если ни один файл содержательно не изменился — коммита быть не должно.

**В пограничных случаях:** при сомнениях, относится ли изменение к содержательным, — пушить. Лишний коммит безопаснее потерянной работы.

**Промежуточные пуши внутри одной сессии — норма**, а не исключение. Несколько коммитов за сессию предпочтительнее одного финального.

## Альтернативы, которые рассмотрели и отклонили
- **Пуш по таймеру (каждые N минут)** — git так не работает, а имитация через cron засорит историю мелкими автокоммитами и не привязана к смысловым границам.
- **Пуш только в конце сессии** (прежнее правило) — приемлемо для коротких сессий, но создаёт окно потери для длинных и для случаев, когда сессия обрывается аварийно.
- **Пушить вообще всё, включая мета-разговоры** — создаёт информационный шум в истории и `journal/`, мешает потом находить реальную работу.
