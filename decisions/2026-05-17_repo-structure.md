# Структура репозитория: по типам задач + контекстные папки

**Дата:** 2026-05-17
**Статус:** принято

## Контекст
На старте было три кандидата структуры:
1. По продуктам (`products/concor`, `products/concor-am`, `products/concor-nst`).
2. По типам задач (`slides/`, `letters/`, `kol-responses/`, `analyses/`, `comparisons/`, `scientific-texts/`).
3. Гибрид.

Поскольку Евгений выполняет задачи разных типов для разных препаратов, и работа в основном идёт от типа задачи к продукту, а не наоборот, продуктовое разделение создавало бы лишний уровень вложенности.

## Принятое решение
Структура «по типам задач + отдельные контекстные папки»:

- `tasks/{slides,letters,kol-responses,analyses,comparisons,scientific-texts}/` — задачи по типу выхода.
- `context/{guidelines,product-info,key-studies,portfolio}/` — справочные материалы.
- `archive/claude-chats/` — перенесённые чаты из claude.ai.
- `templates/` — шаблоны под повторяющиеся форматы.

Препарат фиксируется **в имени файла**: `YYYY-MM-DD_препарат_тема.md`.

## Последствия
- При создании любого нового файла в `tasks/` обязательно указывать препарат в имени.
- Контекстные материалы (рекомендации, инструкции, ключевые исследования) хранятся централизованно — без дублирования по препаратам.
- В `context/product-info/` допускается подпапка по препарату (`konkor/`, `konkor-am/`, `konkor-nst/`), поскольку инструкции/ОХЛП — продукт-специфичны по определению.
