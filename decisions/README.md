# decisions/

Зафиксированные ключевые решения по проекту — соглашения, политики, выбранные подходы, от которых далее работа отталкивается.

**Когда заводить файл здесь:**
- Решение стабильно и применимо далее (а не разовый выбор внутри одной задачи).
- Решение не очевидно из самих правил — например, выбран один из нескольких подходов с trade-offs.
- Полезно иметь возможность сослаться на это решение из других файлов.

**Конвенция именования:** `YYYY-MM-DD_тема.md`.

**Структура файла:**

```markdown
# Заголовок решения

**Дата:** YYYY-MM-DD
**Статус:** принято / отменено / заменено (ссылка на новое решение)

## Контекст
Какая проблема/выбор стоял.

## Рассмотренные варианты
1. Вариант А — плюсы/минусы.
2. Вариант Б — плюсы/минусы.

## Принятое решение
Что именно решили и почему.

## Последствия
Что меняется в работе репозитория, какие файлы/правила затрагивает.
```

Если решение отменяется или заменяется — старый файл не удаляется, статус меняется на «отменено» или «заменено», в начале добавляется ссылка на актуальное решение. История сохраняется.
