# Песочница тестирования промптов

Локальная среда с одной задачей: прогнать кейс через агента → разметить ошибки прямо
в тексте ответа → увидеть, откуда ошибка взялась → накопить замечания для разбора
Claude Code.

Всё, что этой задаче не служит, из интерфейса убрано намеренно.

---

## Запуск

```bash
bash sandbox/set-key.sh     # один раз: спросит ключ и запишет его в sandbox/.env
python3 sandbox/app.py
```

Если порт 8765 занят другим вашим проектом — задайте свой:

```bash
python3 sandbox/app.py --port 8790
```

На Windows вместо первой строки — `sandbox\set-key.bat`.

Ключ вводится скрыто, попадает только в `sandbox/.env` (файл в `.gitignore`,
права 600). Повторный запуск скрипта меняет ключ, остальные настройки сохраняются.

Браузер откроется сам на `http://127.0.0.1:8765`.

Зависимостей нет — только стандартная библиотека Python 3.9+. `pip install` не нужен.

Без ключа песочница поднимается в **mock-режиме**: интерфейс, логи, разметка и пробы
работают на выдуманных ответах, запросы к API не уходят, деньги не тратятся.

Проверить, что всё цело, после любых правок (без обращения к API, бесплатно):

```bash
python3 sandbox/selftest.py
```

Проверить боевой путь — то, что нельзя проверить без ключа: доступна ли модель,
принимает ли она параметры из `models.json`, работают ли эмбеддинги, что поднимает
семантический поиск по базе знаний. Тратит несколько центов:

```bash
python3 sandbox/check-api.py
```

Скрипт печатает отчёт и список того, что надо поправить в `models.json` и
`pricing.json`. Ключ в вывод не попадает.

## Главный принцип: никакой лишней обвязки

Тело запроса — ровно то, что ушло бы при прямом обращении к API:

```json
{"model": "…", "messages": [{"role": "system", "…"}, {"role": "user", "…"}]}
```

Песочница не добавляет ни преамбул, ни служебных пометок, ни разметки вокруг текста.
Если бы добавляла — тест мерил бы песочницу, а не промпт.

Всё, что она всё-таки вынуждена добавить (склейка нескольких файлов, вложение
документов, история диалога, снятый моделью параметр), попадает в список
**отклонений**. Пустой список = `✓ Чистый прогон`. Видно в правой колонке,
вкладка «Почему так вышло».

## Как повторена механика проектов Langdock

Выгрузка их документации лежит в `sandbox/reference/langdock-docs.txt` — всё ниже
оттуда, дословно.

**Главное правило: способ подачи зависит от ЧИСЛА документов, а не от их размера.**

> «When the Agent has up to 20 documents in total, all are previewed in context.
> With more than 20, documents are retrieved through document search instead.»

То есть при 7 файлах Langdock отдаёт модели **все файлы целиком**. Поиск по фрагментам
включается только с 21-го документа — либо сразу, если файлы подключены не прямой
загрузкой, а через Knowledge base или синхронизированную папку.

Отсюда `knowledge_mode` в профиле:

| Значение | Что делает |
|---|---|
| `auto` (по умолчанию) | До 20 файлов — целиком, больше — поиском. Правило Langdock |
| `preview` | Всегда целиком |
| `embedding` | Всегда поиском по фрагментам |

**Параметры поиска — тоже из их документации** (раздел «Our Parameters»):

| Параметр | Langdock | В песочнице |
|---|---|---|
| Размер фрагмента | 2 000 символов | `knowledge_chunk_chars: 2000` |
| Размерность вектора | 1536 | `EMBEDDING_DIMENSIONS = 1536` |
| Фрагментов на запрос | до 50 | `knowledge_top_k: 50` |

**Чего мы не знаем:**

1. Есть ли у предпросмотра потолок объёма. «As much text as possible» намекает, что
   какой-то есть, но он не опубликован. Мы вкладываем файл целиком: для тренажёра это
   ~283 тыс. символов ≈ 100 тыс. токенов на каждое сообщение.
2. Какой моделью Langdock считает эмбеддинги — известна только размерность.
3. **Langdock добавляет к запросу своё.** В разбивке контекста `System prompt` описан
   как «Instructions **and system context**», и отдельно есть категория `System tools` —
   определения инструментов. Ни того, ни другого у нас нет. Это расхождение пока нечем
   закрыть: состав их служебного текста не опубликован.

Расположение: `Attachments` в их разбивке контекста — отдельная категория от
`System prompt`, поэтому файлы уходят отдельным системным сообщением, а не
подмешиваются в инструкции.

**Что это даёт для разбора ошибок.** По каждому замечанию видно, к какой из трёх
причин оно относится:

- термин **был в поданном материале** — модель его получила и всё равно ошиблась,
  чинить надо промпт;
- термин **есть в базе, но не попал в поданное** (только в режиме поиска) — промах
  поиска, модель нужного куска не видела;
- термина **в базе нет вовсе** — пробел базы, модель это достроила сама.

Эти три случая лечатся по-разному, и путать их — значит править не то.

## Рабочий цикл

### 1. Чат

Выбираете профиль и разговариваете с агентом как обычно. Галочка **История** включена —
предыдущие сообщения уходят в контекст, как в настоящей работе. Это нужно для цикла
«клинический случай → разбор → эталон».

### 2. Разметка ошибок

**Выделите мышью любой фрагмент ответа** — откроется форма замечания:

- **часть ответа** — клинический случай / разбор / эталон (угадывается по заголовкам);
- **категория ошибки** — фактическая, выдуманный источник, off-label без дисклеймера,
  формулировка диагноза, метод не даёт этой информации, числа и т. д.;
- **важность** — блокер / существенная / мелкая / заметка;
- **комментарий** — что именно не так.

Замечаний к одному ответу сколько угодно. Размеченные места подсвечиваются и нумеруются.

Списки частей, категорий и важностей правятся в `sandbox/annotation-categories.json` —
это ваш словарь, а не мой.

### 3. Причина, а не догадка

К каждому замечанию автоматически собирается доказательная база:

- **есть ли термины из цитаты в системном промпте** — если модель написала про
  «Конкор НСТ», а слова «НСТ» в промпте нет, писала она это не из вашего контекста;
- **уверенность модели на этом фрагменте** — из `logprobs`. Уверенная ошибка и
  ошибка-угадывание лечатся по-разному. Галочка «Уверенность» появляется только у
  моделей, которые logprobs отдают (gpt-4.1, gpt-4o; у gpt-5.5 по `models.json` — нет);
- **не оборван ли ответ** по лимиту токенов — частая настоящая причина «пропущено важное»;
- какие файлы участвовали, их версии (sha), параметры генерации, коммит репозитория.

Плюс две пробы прямо из карточки замечания:

| Проба | Что отвечает |
|---|---|
| **Повторить ×5** | Повторяет запрос 5 раз со снятым seed. Ошибка воспроизводится каждый раз — системное поведение промпта. Плавает — модель не знает ответа и достраивает случайно. |
| **Абляция** | Прогоняет тот же вопрос без каждого файла промпта по очереди. Если без файла ошибка исчезает — причина найдена вмешательством, а не догадкой. |

**Чего API не даёт вообще:** сырой цепочки рассуждений, весов внимания, активаций.
Виден только счётчик reasoning-токенов. Домысливать эту часть песочница не будет.

### 4. Журнал и замечания

Вторая вкладка. Список прогонов — любой можно **открыть и доразметить**, в том числе
через неделю. Ниже — срез накопленного: какая категория ошибки повторяется чаще, в
какой части ответа.

Две дорожки для Claude Code:

- `sandbox/logs/annotations.jsonl` — по строке на замечание, для разбора;
- `sandbox/logs/ANNOTATIONS.md` — то же для чтения, кнопка «Собрать сводку».

Типичный запрос в Claude Code потом: «прочитай `sandbox/logs/annotations.jsonl`,
найди повторяющиеся категории и предложи правки в промпте».

## Профили

Профиль — что именно тестируется. Обычный Markdown в `sandbox/profiles/`:

```markdown
---
name: Langdock — промпт ассистента
order: 1
model: gpt-5.5
---
Текст системного промпта, байт в байт.
```

Файлы репозитория подключаются списками (оба необязательны):

```markdown
system_files:
  - INSTRUCTIONS.md
context_files:
  - context/product-info/PORTFOLIO_CHEATSHEET.md
```

`system_files` идут в системный промпт как есть; `context_files` — справочные
документы, они помечаются отклонением (см. оговорку про базы знаний выше).

Готовые профили:

| Профиль | Для чего |
|---|---|
| `medrep-simulator` | **Тренажёр Конкор — копия проекта Langdock:** `medrep_prompt_v16.md` в инструкциях + 7 файлов базы знаний поиском по фрагментам. |
| `langdock` | Промпт из Langdock текстом, без файлов. Прогон чистый. |
| `repo-instructions` | `INSTRUCTIONS.md` целиком — проверка правок в самих правилах. |
| `repo-instructions-plus-cheatsheet` | То же плюс cheat-sheet портфеля. |
| `baseline-empty` | Без системного промпта. Точка отсчёта. |

Чтобы сравнить две версии промпта — скопируйте профиль в `langdock-v2.md`, поправьте
текст и переключайтесь между ними. Кнопка `↻` перечитывает профили с диска без
перезапуска сервера.

## Автопроверки

К каждому ответу применяются три дешёвые проверки: запрещённые формулировки из
Блока 2.3 `INSTRUCTIONS.md`, дисклеймер при упоминании off-label, язык ответа.
Результат — в правой колонке. Правятся в `sandbox/checks/default.json`.

Они не оценивают качество по существу — это делает разметка. Они ловят только грубое.

---

## Что где лежит

```
sandbox/
  app.py                      сервер, запускать этим
  selftest.py                 самопроверка в mock-режиме
  .env                        ключ (в git не попадает)
  profiles/*.md               что тестируем
  checks/default.json         автопроверки
  annotation-categories.json  части ответа и категории ошибок
  models.json                 возможности моделей
  pricing.json                тарифы (в интерфейсе не показываются, пишутся в лог)
  logs/                       всё нажитое (в git не попадает)
    runs.jsonl                индекс прогонов
    runs/ГГГГ-ММ-ДД/*.json    полная запись прогона
    runs/ГГГГ-ММ-ДД/*.md      читаемый отчёт
    annotations.jsonl         поток замечаний — основной вход для Claude Code
    ANNOTATIONS.md            сводка замечаний
```

`sandbox/logs/` намеренно вне git: там переписка с моделью и рабочие материалы.
Если конкретный прогон нужно сохранить в репозиторий — `git add -f <путь>`.

## Два файла, которые надо заполнить руками

1. **`models.json`** — возможности `gpt-5.5` (принимает ли `temperature`, отдаёт ли
   `logprobs`) выставлены по семейству gpt-5 и **не проверены**. Если API отвергнет
   параметр, песочница снимет его сама и запишет это в лог как отклонение.

2. **`pricing.json`** — тарифа `gpt-5.5` там нет намеренно: не проверен. В логе будет
   честное «цена не задана» вместо выдуманной цифры.

## Если что-то не так

| Симптом | Причина |
|---|---|
| `Ключ: НЕ ЗАДАН`, режим MOCK | Нет `sandbox/.env` или в нём пустой `OPENAI_API_KEY`. |
| Файл помечен `⚠ не прочитан` | Нет по указанному пути, либо это PDF. PDF намеренно не парсится: парсер — это обвязка, которой нет в тестируемой платформе. Нужен текст — положите рядом `.md`. |
| Нет галочки «Уверенность» | Выбранная модель не отдаёт `logprobs` (по `models.json`). Переключитесь на gpt-4.1, если нужна уверенность по фрагменту. |
| `Address already in use` | Песочница уже запущена в другом окне терминала — просто откройте `http://127.0.0.1:8765`. Свежая версия говорит об этом словами и сама берёт соседний порт, если он занят чужой программой. |
