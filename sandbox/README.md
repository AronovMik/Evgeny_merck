# Песочница тестирования промптов

Локальная среда для проверки того, как промпт-система ведёт себя на реальной модели:
обычный чат с агентом плюс разметка ошибок прямо в тексте ответа и детальный лог,
по которому потом устанавливается **причина** ошибки.

---

## Запуск

```bash
cp sandbox/.env.example sandbox/.env      # один раз
# вписать ключ в OPENAI_API_KEY
python3 sandbox/app.py
```

Браузер откроется сам на `http://127.0.0.1:8765`.

Зависимостей нет — только стандартная библиотека Python 3.9+. `pip install` не нужен,
интернет нужен только для самих запросов к API.

Без ключа песочница поднимается в **mock-режиме**: интерфейс, логи, разметка и пробы
работают на выдуманных ответах, запросы к API не уходят, деньги не тратятся.

Проверить, что всё цело, после любых правок:

```bash
python3 sandbox/selftest.py
```

---

## Главный принцип: никакой лишней обвязки

Тело запроса — ровно то, что ушло бы при прямом обращении к API:

```json
{"model": "…", "messages": [{"role": "system", "…"}, {"role": "user", "…"}]}
```

Песочница не добавляет ни преамбул, ни служебных пометок, ни разметки вокруг текста.
Если бы добавляла — тест мерил бы песочницу, а не промпт.

Всё, что она всё-таки вынуждена добавить (склейка нескольких файлов, вложение
справочных документов, история диалога, снятый моделью параметр), попадает в список
**отклонений**. Пустой список = `✓ Чистый прогон`: запрос эквивалентен прямому вызову.
Это видно в правой колонке при каждом ответе.

**Важная оговорка про базы знаний.** Если в Langdock документы подключены как база
знаний с поиском по фрагментам (RAG), то вкладывание тех же файлов в промпт целиком —
это другой вход, и прямое сравнение результатов невалидно. Такой прогон помечается
отклонением `context_files_inlined` с высокой важностью.

## Рабочий цикл

### 1. Чат

Выбираете профиль и разговариваете с агентом как обычно. Для цикла
«случай → разбор → эталон» оставьте включённой галочку **История** — предыдущие
сообщения уходят в контекст, как в настоящей работе.

### 2. Разметка ошибок

**Выделите мышью любой фрагмент ответа** — откроется форма замечания:

- **часть ответа** — клинический случай / разбор / эталон (угадывается по заголовкам);
- **категория ошибки** — фактическая, выдуманный источник, off-label без дисклеймера,
  формулировка диагноза, метод не даёт этой информации, числа, и т. д.;
- **важность** — блокер / существенная / мелкая / заметка;
- **комментарий** — что именно не так.

Замечаний к одному ответу может быть сколько угодно. Размеченные места подсвечиваются
в тексте и нумеруются.

Списки частей, категорий и важностей правятся в `sandbox/annotation-categories.json` —
это ваш словарь, а не мой.

### 3. Причина, а не догадка

К каждому замечанию автоматически собирается доказательная база:

- **есть ли термины из цитаты в системном промпте** — если модель написала про
  «Конкор НСТ», а слова «НСТ» в промпте нет, писала она это не из вашего контекста;
- **уверенность модели на этом фрагменте** — из `logprobs`. Уверенная ошибка и
  ошибка-угадывание лечатся по-разному;
- **не оборван ли ответ** по лимиту токенов — частая настоящая причина «пропущено важное»;
- какие файлы участвовали, их версии (sha), параметры генерации, коммит репозитория.

Плюс две пробы прямо из карточки замечания:

| Проба | Что отвечает |
|---|---|
| **Стабильность ×5** | Повторяет запрос 5 раз со снятым seed. Фрагмент воспроизводится каждый раз — системное поведение промпта. Плавает — модель не знает ответа и достраивает случайно. |
| **Абляция** | Прогоняет тот же вопрос без каждого файла промпта по очереди. Если без файла ошибка исчезает — причина найдена вмешательством, а не догадкой. |

**Чего API не даёт вообще:** сырой цепочки рассуждений, весов внимания, активаций.
Виден только счётчик reasoning-токенов. Домысливать эту часть песочница не будет.

### 4. Накопленное — во вкладке «Замечания»

Все замечания за всё время: что за категория ошибки повторяется чаще, в какой части
ответа, при каком профиле. Две дорожки для Claude Code:

- `sandbox/logs/annotations.jsonl` — по строке на замечание, для разбора;
- `sandbox/logs/ANNOTATIONS.md` — то же для чтения, кнопка «Собрать сводку».

Типичный запрос в Claude Code потом: «прочитай `sandbox/logs/annotations.jsonl`,
найди повторяющиеся категории и предложи правки в INSTRUCTIONS.md».

## Профили

Профиль — что именно тестируется. Обычный Markdown в `sandbox/profiles/`:

```markdown
---
name: Правила репозитория
model: gpt-5.5
system_files:
  - INSTRUCTIONS.md
context_files:
  - context/product-info/PORTFOLIO_CHEATSHEET.md
---
Дополнительный системный текст (может быть пустым).
```

- `system_files` — файлы правил, идут в системный промпт байт в байт;
- `context_files` — справочные документы (помечаются как отклонение, см. выше);
- тело под шапкой — свой текст промпта.

Готовые профили:

| Профиль | Для чего |
|---|---|
| `langdock` | Ваш промпт из Langdock — вставить текстом. Файлы не подключены, прогон чистый. |
| `repo-instructions` | `INSTRUCTIONS.md` целиком. Проверка правок в самих правилах. |
| `repo-instructions-plus-cheatsheet` | То же плюс cheat-sheet портфеля. Видно, что даёт подмешанная фактура. |
| `baseline-empty` | Без системного промпта. Точка отсчёта: что модель отвечает без правил. |

Кнопка **A/B по профилям** отправляет один вопрос сразу в несколько профилей и
показывает ответы рядом.

## Наборы регресс-тестов

Набор — фиксированные вопросы с ожиданиями (`sandbox/suites/*.md`). Смысл: прогнать
до правки под меткой `база`, после правки — под меткой `после-правки`, и сравнить
пункт за пунктом. В сравнении видно, где улучшение, а где регрессия.

```markdown
## Показания Конкор Кор

### Вопрос
Какие показания зарегистрированы у Конкор Кор?

### Проверки
- contains: ХСН
- contains_any: единственн|только|исключительн
- cites_source
```

Доступные проверки: `contains`, `not_contains`, `contains_any`, `contains_all`,
`regex`, `not_regex`, `max_words`, `min_words`, `max_chars`, `min_chars`,
`cites_source`, `no_forbidden_phrases`, `language_ru`, `off_label_disclaimer`.

Проверки, применяемые к каждому ответу, — в `sandbox/checks/default.json` (там же
список запрещённых формулировок из Блока 2.3 `INSTRUCTIONS.md`).

Ожидания в готовом наборе `konkor-portfolio.md` — мои гипотезы из `context/product-info/`.
Их надо править под себя: набор стоит ровно столько, сколько верны его ожидания.

Галочка **Судья** добавляет оценку ответа отдельной моделью по критериям из шапки
набора. Это отдельный запрос уже после получения ответа — на тестируемый вызов он
не влияет.

## Что где лежит

```
sandbox/
  app.py                      сервер, запускать этим
  selftest.py                 самопроверка в mock-режиме
  .env                        ключ (в git не попадает)
  profiles/*.md               что тестируем
  suites/*.md                 наборы регресс-тестов
  checks/default.json         проверки для каждого ответа
  annotation-categories.json  части ответа и категории ошибок
  models.json                 возможности моделей (параметры, logprobs)
  pricing.json                тарифы для подсчёта стоимости
  logs/                       все прогоны и замечания (в git не попадают)
    runs.jsonl                индекс прогонов
    runs/ГГГГ-ММ-ДД/*.json    полная запись прогона
    runs/ГГГГ-ММ-ДД/*.md      читаемый отчёт
    annotations.jsonl         поток замечаний
    ANNOTATIONS.md            сводка замечаний
    suites/<набор>/<метка>.json  результаты прогонов наборов
```

`sandbox/logs/` намеренно вне git: там переписка с моделью и рабочие материалы.
Если конкретный прогон нужно сохранить в репозиторий — `git add -f <путь>`.

## Два файла, которые надо заполнить руками

1. **`pricing.json`** — тарифа `gpt-5.5` там нет намеренно: я его не проверял, а
   выдуманная цифра в отчёте о стоимости хуже честного «цена не задана». Сверьте с
   openai.com/pricing и впишите.

2. **`models.json`** — возможности `gpt-5.5` (принимает ли `temperature`, отдаёт ли
   `logprobs`) выставлены по семейству gpt-5 и **не проверены**. Если API отвергнет
   параметр, песочница снимет его сама и запишет это в лог как отклонение — но лучше
   поправить здесь заранее.

## Если что-то не так

| Симптом | Причина |
|---|---|
| `Ключ: НЕ ЗАДАН`, режим MOCK | Нет `sandbox/.env` или в нём пустой `OPENAI_API_KEY`. |
| Файл помечен `⚠ не прочитан` | Нет по указанному пути, либо это PDF. PDF намеренно не парсится: парсер — это обвязка, которой нет в тестируемой платформе. Нужен текст — положите рядом `.md`. |
| Пусто в блоке уверенности | Модель не вернула `logprobs`. Включите галочку `logprobs`; если модель их не поддерживает, песочница снимет параметр и напишет об этом в отклонениях. |
| Порт занят | `SANDBOX_PORT=8899` в `.env`. |
