# CLAUDE.md

Этот файл автоматически загружается Claude Code как контекст проекта.

## Базовые инструкции (применяются ВСЕГДА)

Полный свод правил поведения, верификации источников, комплаенс-ограничений и приоритизации — в @INSTRUCTIONS.md. Применять во всех задачах без исключения.

## Контекст проекта

Репозиторий федерального медицинского советника Merck Russia (кардиология). Используется для подготовки материалов по портфелю β-блокаторов (Конкор, Конкор АМ, Конкор НСТ) и для других медицинских/научных задач.

**Портфель Конкор:**
- **Конкор** — бисопролол (β1-селективный адреноблокатор).
- **Конкор АМ** — фиксированная комбинация: бисопролол + амлодипин.
- **Конкор НСТ** — фиксированная комбинация: бисопролол + гидрохлортиазид 6.25 мг.

Инструкции написаны под более широкий портфель (включают упоминания SGLT2-ингибиторов / канаглифлозина) — это не ошибка, они универсальны для всех задач Евгения, не только Конкор.

## Workflow сессии (ОБЯЗАТЕЛЬНО)

**В начале каждой сессии:**
1. Прочитать `STATE.md` — понять, где остановились.
2. Прочитать последнюю запись в `journal/` — увидеть детали предыдущей сессии.
3. Заглянуть в `TODO.md` (раздел Active).
4. Просмотреть `archive/claude-chats/PREVIOUS_CHATS.md` — знать, какие исторические чаты доступны. **Сами файлы чатов читать только по явной команде Евгения** («подтяни чат про…», «загрузи архив по…»). Не подгружать содержимое автоматически.
5. Только после этого приступать к запросу пользователя.

**В конце каждой непустой сессии (перед коммитом):**
1. Обновить `STATE.md`: фокус, последние решения, точка возврата.
2. Добавить запись в `journal/YYYY-MM-DD_короткое-описание.md` по шаблону (см. `journal/README.md`).
3. Обновить `TODO.md`, если появились/закрылись задачи.
4. При принятии крупного стабильного решения — создать файл в `decisions/YYYY-MM-DD_тема.md`.
5. **При переносе нового чата из claude.ai** — добавить запись в `archive/claude-chats/PREVIOUS_CHATS.md` по шаблону (одна запись на чат).
6. Закоммитить с описательным сообщением.

### Когда коммитить и пушить (приоритет — сохранность в GitHub)

Главная цель: если что-то случится с локальной сессией Claude или с аккаунтом Claude в принципе, всё содержательное должно уже быть в репозитории на GitHub.

- **Содержательные изменения пушить как можно скорее, не дожидаясь конца сессии.** К содержательным относятся: новые/изменённые файлы в `tasks/`, `context/`, `decisions/`, `ideas/` (зрелые идеи), `templates/`, `archive/claude-chats/`; обновления `CLAUDE.md` / `INSTRUCTIONS.md` / `STATE.md` / `TODO.md`; журнальные записи по реальной работе. Правило: завершён логически законченный шаг → сразу `commit` + `push`, потом продолжаем.
- **Чисто разговорные сессии не пушить и не журналировать.** Объяснения «что такое X», вопросы про сам Claude Code / git / устройство среды, общие обсуждения, которые не порождают артефактов в репозитории, — оставлять только в чате. Если за сессию ни один файл репозитория содержательно не изменился, коммита быть не должно, запись в `journal/` тоже не нужна.
- **Сомневаюсь, относится ли изменение к содержательным, — пушить.** Лишний коммит безопаснее потерянной работы.
- **Промежуточные пуши внутри длинной сессии — норма**, а не исключение. Несколько коммитов за сессию лучше, чем один в конце.

## Рабочие принципы для этого репозитория

1. **Каждая задача — отдельный файл** в соответствующей подпапке `tasks/`. Именование: `YYYY-MM-DD_короткое-описание.md`.
2. **Используемые источники** перечислять в конце файла задачи (PMID/DOI), даже если они уже лежат в `context/key-studies/`.
3. **Препарат-специфика**: при подготовке материалов для конкретного препарата явно указывать его в заголовке файла (Конкор / Конкор АМ / Конкор НСТ).
4. **Off-label и непрямые сравнения** маркировать в тексте, а не только в комментарии (см. Блок 5 INSTRUCTIONS.md).
5. **Рамка гайдлайнов**: при рецензировании клинических случаев, материалов и постов всегда явно фиксировать, по каким рекомендациям идёт оценка — КР МЗ РФ, ESC, ESH, AHA/ACC или иные. Если рамка не задана пользователем — уточнить до начала разбора. Расхождения между гайдлайнами (например, КР МЗ РФ vs ESC) — отмечать явно, не выбирая «победителя» без запроса.
