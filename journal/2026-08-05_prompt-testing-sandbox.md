# 2026-08-05 — Песочница тестирования промптов

**Ветка:** `claude/chatgpt-api-sandbox-testing-nljo5v`
**Тип работы:** инструмент (не контентная задача)

## Что сделано

Собрана локальная песочница `sandbox/` для тестирования промпт-системы на реальной
модели (OpenAI API, по умолчанию gpt-5.5). Запуск: `python3 sandbox/app.py`,
интерфейс в браузере. Зависимостей нет — только стандартная библиотека Python,
что важно для рабочего ноутбука без прав на `pip install`.

## Ключевые решения

**1. Passthrough вместо обвязки.** Требование Евгения: архитектура песочницы не должна
добавлять харнесс, отличный от Langdock, иначе тесты невалидны. Реализовано так: тело
запроса = `system + messages`, без единого добавленного байта. Всё, что песочница
всё-таки добавляет (склейка файлов, вложение документов, история, снятый параметр),
фиксируется в списке `deviations`. Пустой список = «чистый прогон», видно в интерфейсе.
Отдельно помечается высокой важностью вкладывание файлов знаний целиком: если в
Langdock они подключены как база знаний с поиском по фрагментам, вход отличается и
прямое сравнение невалидно.

**2. Единица логирования — прогон, не сообщение.** Лог ориентирован на тестирование:
отпечаток входа (sha системного промпта и каждого файла, вклад в токенах, версия репо),
точное тело запроса, ответ с usage и задержками, автопроверки, отклонения.

**3. Разметка ответа по фрагментам — основная единица оценки качества.** Рабочий цикл
агента состоит из трёх элементов (клинический случай → разбор → эталон), и оценивать
это одним баллом бессмысленно. Выделение фрагмента открывает форму: часть ответа,
категория ошибки, важность, комментарий. Замечания пишутся и в запись прогона, и в
плоский `logs/annotations.jsonl` — для последующего разбора Claude Code. Словарь
частей и категорий вынесен в `sandbox/annotation-categories.json`.

**4. Причина ошибки устанавливается, а не додумывается.** К каждому замечанию
автоматически собираются факты о входе: есть ли термины из цитаты в системном промпте,
уверенность модели на этом фрагменте (logprobs), не оборван ли ответ по лимиту токенов,
состав файлов и параметры генерации. Плюс две пробы: стабильность (повтор N раз со
снятым seed — устойчивое поведение промпта или случайность) и абляция (прогон без
каждого файла по очереди — установление причины вмешательством).

**5. Граница честности по анализу процесса.** Через API доступны только logprobs и
счётчик reasoning-токенов. Сырая цепочка рассуждений, веса внимания и активации
недоступны — это зафиксировано в README, домысливание не подставляется.

**6. Никаких выдуманных чисел.** Тариф gpt-5.5 намеренно не заполнен в `pricing.json`:
в отчёте пишется «цена не задана». Возможности gpt-5.5 в `models.json` помечены как
непроверенные. Самопроверка поймала, что gpt-5.5 подхватывал цену gpt-5 по префиксу —
исправлено: префикс засчитывается только до дефиса.

## Проверено

`python3 sandbox/selftest.py` — 30 проверок, все проходят (mock-режим, без обращения
к API). Интерфейс проверен в Chromium: выделение фрагмента открывает форму, замечание
сохраняется с доказательной базой, подсветка и правая колонка отрисовываются, ошибок
в консоли нет.

Найдено и исправлено самопроверкой: SSE не закрывал соединение (в браузере не
наступал финал потока); gpt-5.5 тарифицировался как gpt-5; mock-прогоны портили
калибровку счётчика токенов.

## Ревизия интерфейса и урезание до минимума

По требованию Евгения интерфейс сведён к минимуму, закрывающему цель. Осталось две
вкладки вместо пяти: «Чат и разметка» и «Журнал и замечания». В панели управления
пять элементов: профиль, модель, история, «что уйдёт в API», перечитать профили.

Удалено: наборы регресс-тестов с проверками строками (плохо ложатся на творческие
клинические кейсы, где ответ каждый раз новый), модель-судья, сравнение двух прогонов
пословным дифом, A/B по профилям, переключатель темы, ручная оценка 1–5, показ цены
и задержки. Кода стало меньше примерно на треть.

Управление сделано зависимым от модели: галочка `logprobs` появляется только у моделей,
которые их отдают; `Temp` и `Seed` для gpt-5.5 убраны — модель их не принимает, и
параметр молча снимался при отправке.

Добавлено взамен: из журнала любой прошлый прогон открывается в чате и доразмечается —
разметка кейса не обязана заканчиваться в одну сессию.

## Открыто

- Промпт ассистента Langdock не вставлен — профиль `sandbox/profiles/langdock.md`
  ждёт текста. До этого профиль по умолчанию содержит заглушку.
- Не подтверждено, как Langdock подаёт документы: целиком в промпт или через поиск
  по фрагментам. От этого зависит, валидно ли сравнивать профили с `context_files`.
- Тариф gpt-5.5 и его возможности (temperature, logprobs) требуют сверки.
- Вкладка «Наборы тестов» построена под автопроверки строками — под творческие
  клинические кейсы она работает плохо. Судьба вкладки не решена.
