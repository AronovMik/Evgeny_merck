# journal/

Хронологический лог рабочих сессий. Каждый файл — одна сессия или один день работы.

**Конвенция именования:** `YYYY-MM-DD_короткое-описание.md` (или `YYYY-MM-DD.md`, если сессия охватывала несколько разнородных тем).

**Структура записи:**

```markdown
# YYYY-MM-DD — Заголовок

## Контекст
В каком состоянии начинали (что было в STATE.md, какие задачи активны).

## Что сделано
- Конкретные действия, файлы, решения.

## Решения
Зафиксированные на сессии решения и их обоснование. Если решение крупное и стабильное — выносить в `decisions/`.

## Что осталось / следующий шаг
Точка возврата для следующей сессии.

## Затронутые файлы
Список путей.
```

**Принцип:** запись добавляется в конце сессии, до коммита. Если работа в сессии была чисто read-only — запись не обязательна.
